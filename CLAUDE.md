# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

A browser-only constructor for WE Media commercial proposals (КП): the user
pastes their own text (or drops a .docx), it is split into 16:9 slides styled
strictly by `docs/style-guide.md` ("Executive Visibility by WE Media", light
v4), and exported as a vector PDF (browser print), PNG/ZIP or a standalone
HTML deck. It follows the UX logic of `ehroz1/edubridge` (template picker
with live previews, three-pane editor, drafts in localStorage, undo, PWA,
single-file build), but slides are HTML/CSS, not canvas, so the PDF keeps
real text.

UI text, code comments and README.md are in Russian — keep it that way. This
file is in English.

Two content rules from the style guide drive the design: **never rewrite or
add customer text** (the importer only distributes lines into fields; the
only text the app adds is the header label and slide number), and **no
letter-spacing, dark backgrounds, warm accents, rounded corners or shadows**
on slides.

## Commands

```bash
pip3 install fonttools brotli   # optional: subsets fonts (Latin + Cyrillic incl. Kazakh) to woff2
python3 build.py                # writes index.html, manifest.webmanifest, service-worker.js
python3 -m http.server 8000     # clipboard/service worker need http(s), not file://
```

There is no test suite, linter or package.json. Verify changes by building
and driving the page in Chromium (Playwright is in the dev sandbox:
`/opt/node22/lib/node_modules/playwright`). Useful checks:

- render every kind with `sampleData(kind)` and make sure `fitSlide()` keeps
  `k` close to 1 and `overflow` false — the shipped samples should fit;
- `page.pdf({ preferCSSPageSize: true, printBackground: true })` after
  `preparePrint()` with `emulateMedia({ media: 'print' })` reproduces the
  user's "Save as PDF" (1440×810 pt pages, embedded Inter/Montserrat);
- `importText(text)` + `coverage(text, slides)` in Node via `vm` (layouts.js
  + importer.js have no DOM dependency except `htmlToMarkup`/`docxToMarkup`)
  — `missing` must stay 0 for normal texts.

**Always edit `src/`, `brand/` or `build.py`, never the generated
`index.html`.**

## Architecture

`build.py` is plain string templating: `src/index.template.html` gets
`__FONT_FACES__`, `__SLIDES_CSS__`, `__CSS__`, `__ASSETS_JS__`,
`__LAYOUTS_JS__`, `__IMPORTER_JS__`, `__APP_JS__`, `__FAVICON__`,
`__APPLE_TOUCH_ICON__` replaced; the build fails if a token is missing.
Fonts are embedded as `WEInter` (400/500/600/700, italic 500/700) and
`WEMontserrat` (800) — unique names so local installs can't shadow them.
`__GRAIN__` inside `slides.css` is replaced with a deterministic 256×256
noise PNG generated by `grain_png()` (grayscale+alpha, alpha 0–15%).
`__ASSETS_JS__` defines `LOGO` (`{ vb, paths }` from
`brand/logo/we-media-group_black.svg`, drawn with `fill: currentColor`),
`ICONS` (Phosphor Bold SVG markup for the UI), `SLIDE_ICONS`
(`{ name: { svg, kw } }` — Phosphor Duotone inner markup from `brand/icons/`
plus Russian keyword stems from `icons.json`, used for search and
auto-suggest) and `PARTNER_LOGOS` (`[{ id: 'lib:<stem>', name, url }]` from
`brand/partners/*.svg` + `names.json`, the WE media group brands).

The fonts CSS and slide CSS live in `<style id="fontsCss">` and
`<style id="slidesCss">`; PNG and HTML export read them back from there.

Runtime is three classic scripts sharing globals (no modules):

- **`src/layouts.js`** — the single source of truth for slides. One data
  model for every slide (`emptyData()`: `title, lead, note, items[{title,
  text}], label, price, level, big, rows[] (pricing), table{corner,
  priceLabel, cols[{name, price}], rows[{name, cells[]}]}`). `KINDS[kind]`
  = `{ name, group, about, fields: [[key, label]], render(data, env) }`;
  `fields` both drives the form and defines which data the layout shows
  (`slideStrings()`, `hiddenFields()`). Because data is shared, switching a
  slide's kind is lossless; `convertData()` moves items ↔ pricing rows ↔
  table rows when the target field is empty. `render` returns HTML for a
  1920×1080 `.sl` root with `--k` set; `env` = `{ k, num, deck, client,
  preview }` (`preview` shows grey placeholders for empty fields — editor
  only). Text goes through `rich()` = `typo()` (only whitespace changes:
  nbsp after short words without chaining, inside numbers, before dashes) +
  HTML escape + `*accent*` → blue. Every element that maps to a field has
  `data-f="title" | "items.2.text" | …` so a click on the stage focuses the
  form field. Graphics helpers: `bars()`, `rings()`, `gridPanel()`.
  **Swappable graphics:** `SLOTS[kind]` is the box (x, y, w, h, anchor,
  tone, clip) where decoration can live without touching text, the slide
  number or the logo; `gfx(kind, data, defaultHtml)` returns the layout's own
  tuned graphics when `data.gfx` is '' and otherwise a library motif
  (`GFX`: bars, rings, grid, squares, disk, mosaic — `motif()`), nothing for
  'none', or a user image `up:<id>` (`userGraphic()`). `anchor: 'tr'` grows
  from the middle of the right edge so rings never hit the slide number;
  `clip` slots (inside the blue panels) are wrapped and cropped to the box.
  **Item icons:** `item.icon` is `ph:<name>` (SLIDE_ICONS) or `up:<id>`;
  `slideIcon()`/`ico()` render it in the text colour (blue, white on blue).
  User images come from the global `USER_ASSETS` (filled by app.js).
  **Photos:** every kind can carry a user photo (`data.photo` = `up:<id>`
  from `USER_ASSETS.photos`, `photoAt`, `photoFocus`). `renderSlide(kind,
  data, env)` — use it instead of `KINDS[kind].render` everywhere — wraps the
  layout: outer `.sl.slp.at-right|left|half` 1920×1080 with a full-height
  `.ph-col` (`PHOTO_W`: 640 / 960 px) and the unchanged layout as an inner
  `.sl` narrowed to `1920 − --pw`, so the fit loop just reflows the text.
  `PHOTO_MODES` limits modes per kind (half is off where tables/chains/card
  rows would break words; whatwedo is right-only; case uses `'panel'` — the
  photo sits in the bottom of its blue panel, drawn by the case layout
  itself). With a photo `gfx()` returns nothing; layout CSS that assumed the
  full width is overridden under `.slp` at the end of `slides.css`.
  **Partners:** `env.partners` (resolved by app.js) → `partnersHtml()` on the
  cover and contacts top row, max 3.
  `SAMPLE`, `sampleData()` and `STRUCTURES` feed the picker and "+ Слайд".
- **`src/slides.css`** — all slide styling. Every size is
  `calc(Npx * var(--k))`, body text `max(24px, …)` (guide minimum). Elements
  that can overflow carry `data-fit` and `overflow: hidden`. Don't centre
  with `justify-content` inside a `data-fit` box — overflow to the top isn't
  measurable; use `margin: auto` on first/last child (see `.centered`,
  cover, contacts, `.sl-wwd .rc`). No blend modes, masks or SVG filters —
  they break in PDF.
- **`src/importer.js`** — text → slides. `htmlToMarkup()` (clipboard HTML
  from Word/Google Docs) and `docxToMarkup()` (unzips with
  `DecompressionStream('deflate-raw')`, reads styles/numbering) both build
  blocks and call `blocksToMarkup()`, which assigns `#`/`##` by tag/style and
  font size (a top level that appears once at the start is the document
  title, so the next level also becomes slides). The user sees and can edit
  that markup. `parseMarkup()` → blocks (`detectHeadings()` scores plain-text
  headings when there is no `#`), `buildSections()`, then `sectionSlides()`
  picks a kind by heading intent (`INTENTS`) and content shape (item count,
  descriptions, prices, contacts, tables), avoids repeating the previous
  kind and keeps blue `summary` slides ≥ 4 apart; long sections are chunked
  (`CAP`). `coverFrom()` builds the cover (a short first line becomes the
  eyebrow `note`). `digest()` turns blocks into paragraphs and items
  (list + description paragraphs, sub-heading + text, unmarked runs of short
  lines, "Title — text" splits). `slideFromText()` fills one empty slide.
  Newer intents: `quote` (longest line = quote, next lines = author/role),
  `case` (sub-headings → items, a %/×/+ number from the result → `big`),
  `stats` (`NUM_TITLE`/`statItems()` split «120+ публикаций»), `timeline`
  (`TIME_TITLE` periods). `suggestIcon(title, text, used)` /
  `suggestIcons(items)` pick icons by keyword stems (title matches weigh 3×,
  no repeats on a slide, contacts by format).
  `coverage()` checks that every source word is visible on some slide
  (whole lines matched first, then a word pool) — keep it at 0 missing.
- **`src/app.js`** — UI and state. `state.draft` = `{ id, name, createdAt,
  updatedAt, deck: { header, numbers, partners: [ids], partnersMono },
  slides: [{ id, kind, data, tune: { size } }], source }`, autosaved to
  `localStorage` `wekp.drafts.v1` (max 60). User libraries live in
  `wekp.logos.v1`, `wekp.graphics.v1`, `wekp.icons.v1` as `[{ id: 'up:…',
  name, url }]` (rasters downscaled, WebP when the browser can encode it);
  `syncAssets()` loads them into `USER_ASSETS` and the logo index; drafts
  keep only ids. Photos are too big for localStorage: they live in IndexedDB
  (`wekp` / `photos`, `{ id, name, url, thumb, added }`, downscaled to 2000 px
  WebP/JPEG + a 320 px thumb), loaded async by `loadPhotos()` at start;
  `addPhotosToSlide()` handles the «Фото» box upload (multiple), a drop on
  the stage and ⌘V outside inputs. `migrateDeck()` turns the old single `deck.client` logo into
  a library entry + partner id. `normalizeDraft()` /
  `normalizeSlide()` merge old data over `emptyData()` — new fields just get
  defaults; bump the key only for incompatible changes. `fitSlide()` is the
  auto-fit: binary search of `--k` in `[K_MIN, tune.size/100]` rendering into
  a hidden 1920×1080 `.measure` box, cached by `[kind, data, maxK, client]`.
  Previews/thumbnails are the same HTML scaled by CSS transform
  (`paintMini()`; `opts.kind` previews another layout, `opts.data` other
  data — used by the «Раскладка» and «Графика» pickers). Undo snapshots `{ slides, deck, name, current }`; a tag
  coalesces typing bursts. Export: PDF = fill `#printRoot` with all slides +
  `@page { size: 1920px 1080px; margin: 0 }` + `window.print()` (also on
  ⌘P via `beforeprint`); PNG = slide HTML serialized into an SVG
  `foreignObject` with the embedded font/slide CSS, drawn to canvas; HTML =
  standalone file with fonts, slide CSS and a tiny viewer.

UI shape follows edubridge.media (pill buttons, 20–28 px card radii, thin
outlines instead of shadows, editor panels as separate rounded cards); the
slides themselves keep square corners per the style guide.

Dark theme covers only the app chrome; slides always use brand colours.
Theme variables live in two blocks in `styles.css` that must stay in sync
(`prefers-color-scheme` and `[data-theme="dark"]`).

Mobile (< 900px): the workspace stacks (stage, horizontal slide strip,
form). Modals use `grid-template-columns: minmax(0, 1fr)` so content can't
widen the viewport.
